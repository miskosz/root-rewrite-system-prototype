Root Rewrite System (RRS) is a model of computation operating on \emph{terms}. The
definitions below use ideas from term rewriting systems and functional
language features in e.g. ML, Haskell or Rust.

\section{Signatures and Terms}

Definitions in this section follow the term rewriting systems theory.

Throughout, we fix a countably infinite set $\Variables$ of \emph{variables},
disjoint from any other set we consider (in particular from the constructors of
any signature). As a convention, $x, y, z \in \Variables$.

\begin{definition}[Signature]
A \emph{signature} is a tuple $(\Constructors, \arity)$ where:
\begin{itemize}
  \item $\Constructors$ is a finite set;
  \item $\arity \colon \Constructors \to \N$ is a function.
\end{itemize}
Constructors of arity zero are called \emph{constants}, of arity one
\emph{unary} and of arity two \emph{binary}.
\end{definition}

\begin{definition}[Terms]
Let $(\Constructors, \arity)$ be a given signature. For $V \subseteq \Variables$ define $\Terms(V)$, the set of
\emph{terms with variables in $V$,} as the smallest set such that:
\begin{itemize}
  \item $V \subseteq \Terms(V)$;
  \item For a constant $C \in \Constructors$ we have $C \in \Terms(V)$;
  \item For $C \in \Constructors$ with $n := \arity(C) > 0$ and $t_1, \dots, t_n \in \Terms(V)$
        we have $C(t_1, \dots, t_n) \in \Terms(V)$.
\end{itemize}
\end{definition}

We understand terms as trees rather than strings. In particular, rooted trees with ordered
children. The leaves are variables and constants, and inner nodes are constructors
with as many children as is their arity.

\begin{definition}[Term variables]
Let a signature be given and $t \in \Terms(\Variables)$. Define $\Var(t)$, the
\emph{variables occurring in $t$}, as the smallest $V \subseteq \Variables$ such that
$t \in \Terms(V)$. If $V$ is the empty set we call $t$ \emph{ground}.

The set of
all ground terms is denoted simply $\Terms$, and the set of all terms with
variables, $\Terms(\Variables)$, is denoted $\TermsVar$.
\end{definition}

\begin{example}[Natural numbers]\label{ex:natural-numbers}
Let us construct terms representing natural numbers. We define the signature by:
\begin{align*}
  \Constructors &= \{\rrsname{Zero}, \rrsname{Succ}\} \\
  \arity \colon \Constructors &\to \N \\
  \rrsname{Zero} &\mapsto 0 \\
  \rrsname{Succ} &\mapsto 1
\end{align*}
Example terms representing 0, 1, 2 are:
\begin{itemize}
  \item $\rrsname{Zero}$
  \item $\rrsname{Succ}(\rrsname{Zero})$
  \item $\rrsname{Succ}(\rrsname{Succ}(\rrsname{Zero}))$
\end{itemize}
These are ground, and all are elements of $\Terms$. An example element of $\TermsVar$
is $\rrsname{Succ}(\rrsname{Succ}(x))$.
\end{example}

\begin{definition}[Substitution]
Let a signature be given. A map $\sigma \colon \Variables \to \Terms$ is
called \emph{a substitution.} We naturally extend $\sigma$ to a map
$\hat{\sigma} \colon \TermsVar \to \Terms$ as follows:
\begin{itemize}
  \item For $x \in \Variables$ we have $\hat{\sigma}(x) := \sigma(x)$;
  \item For a constant $C \in \Constructors$ we have $\hat{\sigma}(C) := C$;
  \item For $C \in \Constructors$ with $n := \arity(C) > 0$ and $t_1, \dots, t_n \in \TermsVar$
        we have $\hat{\sigma}(C(t_1, \dots, t_n)) := C(\hat{\sigma}(t_1), \dots, \hat{\sigma}(t_n))$.
\end{itemize}
\end{definition}

\section{Root Rewrite Systems}

Now that we have the definition of terms and related concepts, the definition
of a root rewrite system is rather straightforward.

\begin{definition}[Rewrite rule]
Let a signature be given. A \emph{rewrite rule} is a tuple
$(\tleft, \tright) \in \TermsVar^2$ such that:
\begin{itemize}
  \item every variable in $\tleft$ occurs at most once;
  \item every variable in $\tright$ occurs at most once;
  \item every variable in $\tright$ occurs in $\tleft$.
\end{itemize}
A rewrite rule \emph{matches} a term $t \in \Terms$ if there exists a substitution $\sigma$
such that $\hat{\sigma}(\tleft) = t$. In that case, $\hat{\sigma}(\tright)$ does not depend
on the choice of $\sigma$ and we call it \emph{$t$ rewritten by the rule}.
\end{definition}

Note that the rules do not allow for duplication of variables. Subterms bound by variables can
only be moved around or discarded.

\begin{definition}[Root Rewrite System]
A \emph{Root Rewrite System} is a tuple $\rrsname{RRS} = (\Sig, \Rules)$
where $\Sig$ is a signature and $\Rules$ is an ordered list of rules.

Given an input term $t_0 \in \Terms$, in one \emph{step} the machine rewrites
$t_i \to t_{i+1}$ using the first matching rule. The sequence
terminates at $t_n$ if no rule matches; then $t_n$ is the output of the machine.
If the sequence does not terminate the machine does not produce an output.
\end{definition}

\begin{note}
In term rewriting terminology this is a \emph{priority root-rewrite system}: rules apply
only at the root, and the first matching rule wins. Moreover, the rules are \emph{linear.}
Note that $t_n$ defined above is the \emph{normal form} of $t_0$.
\end{note}

We define a simple programming language to give examples of RSSes. A program is of the form:

\begin{rrscode}
rule <lhs1> -> <rhs1>
rule <lhs2> -> <rhs2>
...
\end{rrscode}

Every line defines a rewrite rule, ordered from top to bottom. The signature is implicitly
defined as the set of all constructors occurring in the rules, with arity given by their
usage (which must be consistent). To distinguish constructors from variables, we require that
constructors start with an uppercase letter and variables with a lowercase one.

\begin{example}[Addition of natural numbers]
With the natural number definition from Example \ref{ex:natural-numbers}, let us add an
$\rrsname{Add}$ constructor with arity two:

\begin{rrscode}
rule Add(Succ(x), y) -> Add(x, Succ(y))
rule Add(Zero, y) -> y
\end{rrscode}

The idea is to move all $\rrsname{Succ}$ constructors from the first child to the second
one-by-one. I.e., $\rrsname{Add}(x+1, y)$ rewrites to $\rrsname{Add}(x, y+1)$. A computation
of 2+1 looks like this:
\begin{align*}
  &\rrsname{Add}(\rrsname{Succ}(\rrsname{Succ}(\rrsname{Zero})), \rrsname{Succ}(\rrsname{Zero})) \\
  {}\to{} &\rrsname{Add}(\rrsname{Succ}(\rrsname{Zero}), \rrsname{Succ}(\rrsname{Succ}(\rrsname{Zero}))) \\
  {}\to{} &\rrsname{Add}(\rrsname{Zero}, \rrsname{Succ}(\rrsname{Succ}(\rrsname{Succ}(\rrsname{Zero})))) \\
  {}\to{} &\rrsname{Succ}(\rrsname{Succ}(\rrsname{Succ}(\rrsname{Zero})))
\end{align*}
which is the term representing 3, as expected.

\end{example}

\begin{example}[Lists]
As customary in functional languages\footnote{The arity-two constructor is usually named
$\rrsname{Cons}$. We name it $\rrsname{L}$ for brevity.}, we represent lists with two constructors,
$\rrsname{Nil}$ of arity 0 and $\rrsname{L}$ of arity 2. $\rrsname{Nil}$ represents an empty list,
and $\rrsname{L}(head, tail)$ a list with $head$ as the first element and $tail$ as the rest
of the list.

For example, if $\rrsname{True}$ and $\rrsname{False}$ are constants, this is a valid three-element
list:
\begin{align*}
\rrsname{L}(\rrsname{True}, \rrsname{L}(\rrsname{False}, \rrsname{L}(\rrsname{False}, \rrsname{Nil})))
\end{align*}

Because lists are very useful we introduce a right-associative $head :: tail$
shorthand notation for $\rrsname{L}(head, tail)$. The same list can be written as:
\begin{align*}
\rrsname{True} :: \rrsname{False} :: \rrsname{False} :: \rrsname{Nil}
\end{align*}
\end{example}

\begin{example}[Reversing a list]
Let lists be as in the previous example. We can define a reverse function with
the following rules:
\begin{rrscode}
rule Reverse(list) -> ReverseImpl(list, Nil)
rule ReverseImpl(head :: tail, revlist)
    -> ReverseImpl(tail, head :: revlist)
rule ReverseImpl(Nil, revlist) -> revlist
\end{rrscode}
We introduced an auxiliary constructor $\rrsname{ReverseImpl}$ to reverse the input
into an accumulator element by element.
\end{example}

The examples above show some properties of using RRS as a programming language:
\begin{itemize}
\item We use some constructors to represent functions and some to represent data. In the
examples above the root represents a function and the rest is data, however the
distinction between functions and data is not always clear.
\item For lists, it is often useful to restrict $head$ to always be of the same "type".
We will later on introduce types formally for a much broader range of usecases.
\item The $\rrsname{Reverse}$ example works for lists of any element type.
\item Introducing auxiliary functions is a common programming technique in RRS.
\end{itemize}

We will return later to using RRS as a programming language. First we will explore
some theoretical properties of this model of computation.

\begin{exercise}
Define a function $\rrsname{ListLength}$ that computes the length of a list.
The output should be a natural number as defined in Example \ref{ex:natural-numbers}.
\end{exercise}

\begin{exercise}
Define a function $\rrsname{IsPalindrome}$ that checks if a list is a palindrome.
You can assume a finite set of constants to represent the elements of the list, e.g.,
$\rrsname{True}$ and $\rrsname{False}$. The output should be a boolean.
\end{exercise}

\section{Properties of Root Rewrite Systems}

In this section we compare RRS to other models of computation and discuss some of its
properties. We start by showing that an RRS can simulate a Turing machine with
precisely the same number of steps. This shows that RRS is Turing-complete.

\subsection{Turing-completeness}

The first technical obstacle to navigate is which Turing machine flavour to choose
for our analysis. They differ in the output mode -- they can accept or reject, or they
can produce an output. We can also choose the number of tapes.

The choice will matter later on when we look at complexity classes. For now, we choose
the simple case of a single-tape decision Turing machine. Other flavours can be
simulated analogously.

\begin{definition}[Turing machine, Sipser's definition] A deterministic single-tape decision
\emph{Turing machine} is a 7-tuple $(Q, \Sigma, \Gamma, \delta, q_0, q_{accept}, q_{reject})$
where:
\begin{itemize}
  \item $Q$ is a finite, non-empty set of \emph{states};
  \item $\Sigma$ is a finite set of \emph{input symbols}, not containing the blank symbol
  $\sqcup$;
  \item $\Gamma$ is a finite set of \emph{tape symbols}, where $\Sigma \subseteq \Gamma$
  and $\sqcup \in \Gamma$;
  \item $\delta \colon Q \times \Gamma \to Q \times \Gamma \times \{L, R\}$ is the
  \emph{transition function};
  \item $q_0, q_{accept}, q_{reject} \in Q$ are the \emph{start state},
  \emph{accept state} and \emph{reject state} respectively, where $q_{reject} \neq q_{accept}$.
\end{itemize}
We omit the formal definition of the machine's configuration and how it operates.
We assume the reader is familiar with Turing machine operation.
\end{definition}

\begin{definition}[Number of steps]
Let $M_{TM}$ be a Turing machine and $w \in \Sigma^*$ an input word. Let
$\Steps_{TM}(M_{TM}, w)$ denote the number of steps $M_{TM}$ takes on input $w$
until it halts, or $\infty$ if it does not halt.

Similarly, for $M_{RRS}$ an RRS and $T \in \Terms$ a compatible input term we define
$\Steps_{RRS}(M_{RRS}, T)$ as the number of steps $M_{RRS}$ takes on input $T$ until
it halts, or $\infty$ if it does not halt.

If the model of computation is clear from context, we write simply
$\Steps(M, input)$ for brevity.
\end{definition}

\begin{theorem}[RRS simulates TM with the same number of steps]
For every Turing machine $M$ there exists an RRS $\hat M = (\Sig, \Rules)$
with $C_{accept}, C_{reject} \in \Sig$ and an encoding $\tau \colon \Sigma^* \to \Terms$
such that:
\begin{itemize}
  \item $\Steps(M, w) = \Steps(\hat M, \tau(w))$ for all $w \in \Sigma^*$;
  \item $M$ halts in an accept state on input $w$ if and only if $\hat M$ halts
  in a term with $C_{accept}$ as the root constructor on input $\tau(w)$.
  Analogously for the reject state.
\end{itemize}
\end{theorem}

The proof idea is to encode the Turing machine's configuration as a term, where the
root constructor represents the current state, and has two children: the list of tape
symbols to the left of the head, and the list of tape symbols to the right of it. The
left list is reversed so that the symbol closest to the head is at the top.

\begin{proof}
Let $M = (Q, \Sigma, \Gamma, \delta, q_0, q_{accept}, q_{reject})$. WLOG assume that
$Q$, $\Gamma$ and the set of list constructors $\{\rrsname{L}, \rrsname{Nil}\}$
are disjoint.

Define the signature $\Sig = (\Constructors, \arity)$ of $\hat M$ such that:
\begin{itemize}
  \item $\Constructors = Q \cup \Gamma \cup \{\rrsname{L}, \rrsname{Nil}\}$;
  \item $\arity(q) = \arity(\rrsname{L}) = 2$ for $q \in Q$ and
  $\arity(s) = \arity(\rrsname{Nil}) = 0$ for $s \in \Gamma$.
\end{itemize}

Define $\tau(\varepsilon) := q_0 (\rrsname{Nil}, \sqcup :: \rrsname{Nil})$ and for
$s_1 s_2 \cdots s_n \in \Sigma^+$ define:
\begin{align*}
  \tau(s_1 s_2 \cdots s_n) := q_0 (\rrsname{Nil}, s_1 :: s_2 :: \dots :: s_n :: \rrsname{Nil})
\end{align*}

Finally, for $(q, s) \in Q \times \Gamma$ define rules:
\begin{itemize}
  \item If $\delta(q, s) = (q', s', L)$:
  \begin{itemize}
    \item $q(\rrsname{Nil}, s :: rtail) \to q'(\rrsname{Nil}, \sqcup :: s' :: rtail)$
    \item $q(t :: ltail, s :: rtail) \to q'(ltail, t :: s' :: rtail)$
  \end{itemize}
  \item If $\delta(q, s) = (q', s', R)$:
  \begin{itemize}
    \item $q(l, s :: \rrsname{Nil}) \to q'(s' :: l, \sqcup :: \rrsname{Nil})$
    \item $q(l, s :: rtail) \to q'(s' :: l, rtail)$
  \end{itemize}
\end{itemize}

This construction simulates the Turing machine step-by-step, as we invite the reader
to verify. A formal proof would need a formal definition of the Turing machine's
configuration and operation, which we omit here for brevity.

The proof is finished by setting $C_{accept} := q_{accept}$ and $C_{reject} := q_{reject}$.
\end{proof}

It is not difficult to convince oneself that a Turing machine can simulate an RRS with
at most a polynomial factor overhead. In every RRS step, the term size in the number
of nodes can grow at most by a constant. For a simulation by a Turing machine, we can
encode the term as a string with parentheses and commas. With this representation,
rule matching and rewriting can be done in linear time in the size of the term.
We present the proof in Appendix \ref{appendix:tm-simulates-rrs} for completeness.

\begin{lemma}[TM simulates RRS with polynomial overhead]
For every RRS $R$ there exists a multi-tape Turing machine with an input-output tape
$\hat R$ and an encoding $\tau \colon \Terms \to \Sigma^*$ such that:
\begin{itemize}
  \item $\Steps(\hat R, \tau(T)) = O(S|T| + S^2)$ for all $T \in \Terms$, where $S = \Steps(R, T)$;
  \item If $R$ produces an output $T'$ on input $T$, then $\hat R$ halts on input $\tau(T)$
  and produces $\tau(T')$ on the input-output tape. Otherwise, $\hat R$ does not halt on input $\tau(T)$.
\end{itemize}
\end{lemma}

Since a single-tape Turing machine can simulate a multi-tape Turing machine with at most
a quadratic overhead, we can conclude that RRS and Turing machines are polynomially equivalent
models of computation. In particular:

\begin{corollary}
RRS is Turing-complete.
\end{corollary}
